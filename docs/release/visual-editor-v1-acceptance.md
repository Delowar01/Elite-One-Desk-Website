## How to read this

| Status | Meaning |
|---|---|
| **PASS** | Implemented, enforced where it matters on the server, and proved by at least one tracked check that ran green on the release candidate. |
| **PASS WITH DOCUMENTED LIMITATION** | As PASS, inside a boundary V1 chose deliberately. The boundary is written beside it. Never an unresolved defect. |
| **NOT APPLICABLE** | The requirement does not apply to this product, with the reason. (None.) |
| **FAIL** | Not met. (None.) |

- **No PASS rests on source alone.** Every row names its tracked evidence — a
  test in `tests/*.test.ts` (**T**, by its exact title), a browser-probe line
  (**P**, `tests/browser/probes/<name>.probe.mts`) or a stress line (**S**,
  `tests/stress/<name>.stress.mts`) — and every citation was checked
  mechanically against the titles and lines the release candidate's own runs
  printed. A row whose only support was the code was a GAP until a check was
  written for it.
- The 268 requirements were collected from the Batch 1–19A briefs and commits
  (the **Origin** column; `§n` is the 19B brief's section). The matrix
  skeleton — every requirement, all *pending* — was written before any
  source changed in 19B (it was not committed on its own: this file enters
  the history complete, with the release candidate).
- Implementation and server authority name the file and, after `::`, the
  function or export that carries the requirement.

without the fix — shown by running the check with the fix taken out.

Not in V1: text-transform, an independent letter-spacing control (tracking
rides the size step), any physical side, any length, unit, `calc()`,
selector, class or `var()` from input.

**Responsive.** Base is the inline style; Tablet and Mobile are sparse
branches written as `--rs-t-*` / `--rs-m-*` custom properties behind one fixed
rule per property at `max-width: 1024px` and `640px` (screen only, so print
gets Base). Inheritance is the cascade, Base → Tablet → Mobile.

**Reset and Inherit.** *Reset* on an element removes its overrides at the
width being edited and saves an explicit empty document, so publishing it
removes them from the live page; `null` means "nothing pending" and an empty
document means "publishing removes every override" — the difference is
load-bearing. *Inherit* at Tablet or Mobile removes that branch's key and the
control reads "Inherited from …".

**Which node offers what** is derived from the block registry, never listed:
section roots get surface, spacing, layout and visibility; text gets type,
colour, margin, width and opacity; media gets frame, focal point and size;
slots, containers and rows get layout. Advanced tokens need
`content.advanced_style` as well as `content.style`; the server compares every
advanced token with the stored baseline and refuses an add, change, removal
or reset without it.

## Accepted V1 limitations

Intentional boundaries — none of them is an unresolved defect:

1. **Word Reveal is word-based**, not line- or character-based; a text over 24
   words is not split (MO-L1).
2. **No Hover Glow.** Hover is None / Lift / Scale / Zoom / Nudge; glow stays a
   Style token, the one owner of box-shadow (MO-L2).
3. **Legacy basic motion presets keep their legacy CSS classes**, and every
   motion write also stores the nearest legacy preset so a rollback renders
   sensibly (MO-L3).
4. **Live parallax is paused in the editor canvas**; Replay previews it with a
   bounded sweep, and Preview and the public site run it live (MO-L4).
5. **Four system role types** (owner, admin, editor, viewer) with any
   combination of granular keys; no arbitrary named custom roles in V1.
6. **The Stress workflow runs by hand or on a schedule**, not on every push.
7. **Browser QA runs in Chromium only.**
8. Whole-block reuse for final-cta, rich-text and image-text only; every
   other block's CTA slots stay linkable (RC-02). Component history keeps the
   30 most recent replaced versions (RC-06). Gap is offered wherever the
   effective layout is flex or grid (SB-06, broadened in Batch 14).
9. The Layers and Inspector panels appear from 1280 px wide; below that the
   editor is its toolbar and canvas.
